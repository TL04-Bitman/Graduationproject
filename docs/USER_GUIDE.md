# 使用手册（USER GUIDE）

> 面向**不使用命令行也不懂数据库**的教务老师与学生。全部操作都是「选数字 + 回车」。

---

## 0. 启动系统

```bash
cd ~/pro1
bash run.sh
```

首次使用需要先准备数据库与演示数据（只需一次）：

```bash
bash scripts/setup_local_mysql.sh     # 没有 MySQL 时执行, 自动安装并启动
bash run.sh init                      # 建表 + 导入演示数据
bash run.sh                           # 进入界面
```

进入后看到主菜单：

```
    1. 教务排课        (一键排课 / 拓扑序 / 循环依赖检测 / 全校课表)
    2. 课程与先修关系  (课程列表 / 先修关系维护, 自动阻止成环)
    3. 学生端          (登录后选课 / 退课 / 查看我的课表)
    4. 效率基准测试    (本系统策略 vs 朴素试错策略, 实测提升比例)
    5. 系统信息        (数据库连接 / 数据规模 / 初始化)
    0. 退出
请选择功能 [0-5]:
```

- 任何菜单里输入 `0` 都表示**返回上一级**；
- 每个页面底部会提示「按回车键返回」，看到结果后按一次回车即可回到菜单；
- 输入非数字或超范围会提示重输，不会误操作。

## 1. 教务老师操作路径

### 1.1 一键排课（最常用）

`主菜单 → 1 教务排课 → 1 一键排课`

1. 直接回车使用当前学期（默认 `2026-2027-1`）；
2. 屏幕会显示本学期课程数、教学班数、已有排课记录数；
3. 输入 `y` 确认，系统依次完成：读取先修关系建图 → 拓扑排序校验 → 分配时段与教室 → 写库 → 自检。

完成后你会看到：

```
✔ 排课完成
  学期: 2026-2027-1  算法: kahn-topological-greedy  模式: 正式(已落库)
  课程(顶点): 27  教学班: 30  需要课次: 51  成功课次: 51
  冲突检测次数: 515  冲突重试次数: 372  未排成功教学班: 0
  耗时: 52 ms  成功率: 100.0%
  排课自检: 教师冲突=0 教室冲突=0 班级冲突=0
```

- **成功率 100%** 表示所有教学班都排上了；若有个别班级排在"需人工处理的教学班"表格里，
  表格会写明原因（例如"教师已达工作量上限""时段/教室资源不足"），按提示调整教师或教室后重排即可。
- 重复执行排课会**覆盖**该学期原有结果（界面会提示），不会产生重复数据。

### 1.2 查看排课顺序（拓扑序与分层）

`1 教务排课 → 2 拓扑排序与分层`

- 上半部分是**先修分层**：第 0 层是没有先修课的课程（可安排在第一学年），层数越大越靠后；
- 下半部分是**拓扑排序结果**：系统的排课优先级顺序 —— 先修课排前面，优先占用上午的时段。

### 1.3 检查教学计划有没有"循环依赖"

`1 教务排课 → 3 循环依赖检测`

```
拓扑序列长度 = 27, 课程总数 = 27
✔ 检测通过: 教学计划无循环依赖
```

若存在循环依赖（例如有人在教学计划里把 A 设成 B 的先修、又把 B 设成 A 的先修），会显示：

```
✘ 检测失败: 检测到课程循环依赖
拓扑序列长度 22 ≠ 课程总数 27
环路路径: CS101 → CS202 → CS205 → CS306 → CS311 → CS101
建议: 删除环路中的一条先修关系(见菜单 2)
```

**请照"环路路径"里列出的课程，去菜单 2 删除其中一条先修关系**，再重新检测。

### 1.4 循环依赖演练（给领导/评审演示用）

`1 教务排课 → 4 循环依赖演练`

系统会临时写入一条错误先修关系（模拟教学计划录入错误），然后演示：
① 自动检测出环路 → ② 排课被自动中止 → ③ 证明没有写入任何脏数据 → ④ 自动恢复现场。
整个过程无需人工清理，最后会给出"循环依赖可在排课前 100% 拦截"的结论。

### 1.5 其他教务查询

| 菜单 | 用途 |
| --- | --- |
| `5 全校课表` | 按教学班查看上课时间、教室、选课人数/容量 |
| `6 教师工作量` | 每位教师的教学班数、每周课次、是否超过工作量上限 |
| `7 教室使用率` | 每间教室已占时段数与使用率（进度条形式） |
| `8 学生选课情况` | 每位学生的选课门数与学分 |
| `9 排课审计记录` | 每次排课的时间、耗时、成功课次数、状态 |

### 1.6 维护课程先修关系

`主菜单 → 2 课程与先修关系`

- `1 课程列表`：课程编号、名称、学分、类型、每周节次、已有先修课；
- `2 先修关系一览`：逐条列出「后续课程 ← 先修课程」；
- `3 新增先修关系`：依次输入"后续课程编号"和"先修课程编号"（如 `CS312` / `CS301`）。
  **若这条关系会造成循环依赖，系统会拒绝写入并列出环路**，教学计划不会被破坏；
- `4 删除先修关系`：输入课程编号对即可删除，删除后会立即重新做一次环检测。

## 2. 学生操作路径

`主菜单 → 3 学生端`，输入学号与口令（演示账号与口令如下），回车登录：

| 学号 | 姓名 | 年级 | 特点 |
| --- | --- | --- | --- |
| `2024001` | 张明 | 大三 | 先修齐全，可选的课最多（默认账号，直接回车即可） |
| `2025001` | 冯雪 | 大二 | 修完高数与程序设计基础，可选专业基础课 |
| `2026001` | 吕佳 | 大一 | 无历史成绩，只能选没有先修要求的课程 |

口令统一为 `123456`。

### 2.1 我的课表（查课）

`学生端 → 1 我的课表`

```
┌───────────────┬───────────────────┬───────────────────┬───────────────────┐
│ 节次 / 时间   │ 星期一            │ 星期二            │ 星期三            │
├───────────────┼───────────────────┼───────────────────┼───────────────────┤
│ 第 1 大节     │ —                 │ 计算机组成原理    │ 计算机组成原理    │
│ 08:00-09:40   │                   │ 陈静 / A102       │ 陈静 / A101       │
├───────────────┼───────────────────┼───────────────────┼───────────────────┤
│ 第 2 大节     │ 数据结构与算法    │ 数据库原理        │ —                 │
│ 10:00-11:40   │ 张伟 / A101       │ 李娜 / A101       │                   │
└───────────────┴───────────────────┴───────────────────┴───────────────────┘
```

- 网格下方还有明细表（课程 / 教学班 / 教师 / 时间 / 地点 / 学分 / 状态）；
- 若某门课"已选但尚未排课"，会单独提示——等教务完成排课后会自动出现在课表中。

### 2.2 看能选哪些课

`学生端 → 2 可选课程列表`

每门课都会给出**能不能选**与**不能选的原因**：

| 状态 | 含义 | 怎么办 |
| --- | --- | --- |
| 可选 | 满足全部条件，可以选 | 直接去 `3 选课` |
| 已选 | 你已经选过这门课 | 无需重复选 |
| 先修未满足 | 缺少先修课并已列出课程编号 | 先修并通过该先修课 |
| 时间冲突 | 与已选课程的上课时间重叠（列出冲突课程与时段） | 改选其他教学班，或退掉冲突课程 |
| 超出学分上限 | 加上这门课会超过本学期学分上限（默认 25） | 先退掉其他课程 |
| 容量已满 | 教学班人数已满 | 选择同一课程的其他教学班 |
| 尚未排课 | 该班还没排课 | 等教务完成排课 |

### 2.3 选课与退课

- `3 选课`：输入教学班编号（如 `CS204-01`），成功会显示上课时间与累计学分；
- `4 退课`：先显示你已选的班级列表，输入教学班编号即可退选（退课保留历史记录，便于追溯）。

演示用的典型结果：

```
输入 CS204-01 → ✔ 张明 成功选修《数据库原理》(CS204-01), 上课时间: 星期二 · 第 2 大节、星期五 · 第 1 大节, 当前学期累计 10.5 学分
输入 MA201-01 → ✘ 与已选课程时间冲突: 计算机组成原理 · 教学班01(星期三 · 第 1 大节)、数据结构与算法 · 教学班01(星期四 · 第 1 大节)
（大一学生选 CS204-01）→ ✘ 先修课程未通过: CS201(需成绩 ≥ 60 分)
```

### 2.4 先修进度与历史成绩

- `5 先修进度`：列出所有"有先修要求"的课程，以及你**已满足 / 待补**的先修课；
- `6 我的成绩`：历史修读状态（已完成/不及格/在修）与累计已通过学分。

## 3. 效率基准测试（可选）

`主菜单 → 4 效率基准测试 → 1 运行基准测试`

同一份数据下对比两种排课策略，输出耗时、冲突检测次数与差距百分比。
`2 规模扫描` 会展示教学班规模从 30 增加到 180 时两种策略的差距变化。

> 提示：该页面只做计算（不写数据库），可以放心反复运行。

## 4. 出问题了怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动时报「无法连接 MySQL」 | 本地 MySQL 实例没启动 | `bash scripts/mysql_ctl.sh start`，或重新执行 `bash scripts/setup_local_mysql.sh` |
| 提示「数据库中没有数据」/ 表为空 | 还没导入演示数据 | `bash run.sh init` |
| 排课报「检测到循环依赖」 | 教学计划的先修关系成环 | 按提示的"环路路径"到菜单 2 删除一条先修关系 |
| 选课报「教学班尚未完成排课」 | 排课还没做 | 先到 `1 教务排课 → 1 一键排课` |
| 选课报「时间冲突」 | 与已选课程时段重叠 | 改选同一课程的其他教学班，或先退课 |
| 中文表格错位 | 终端宽度小于 80 列 | 把窗口拉宽（系统按终端宽度自适应） |
| 想要清空重来 | —— | `5 系统信息 → 3 初始化/重建演示数据`（会清空重导，谨慎） |

更多技术细节见 [HANDOVER.md](HANDOVER.md)。
