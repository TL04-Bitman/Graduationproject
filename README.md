# 学生课表排课系统（C++17 / MySQL / DAG 拓扑排序）
指导老师：吴光伟
一个模拟高校教务处日常工作的**终端排课系统**：把课程先修关系抽象成 **DAG（有向无环图）**，
用 **Kahn 算法**做拓扑排序，据此完成「一键排课」，并提供学生选课 / 退课 / 查课表等完整业务流程。
所有界面均为中文终端可视化界面（表格、周课表网格、进度条、流程图），非技术用户即可直接上手。

## 一、核心特性

| 特性 | 说明 |
| --- | --- |
| **先修建模为 DAG** | 27 门课程、33 条先修关系构成有向图，边方向为「先修课 → 后续课」 |
| **Kahn 算法拓扑排序** | 逐层剥离入度为 0 的顶点，O(V+E)；就绪队列按「先修层级 + 课程编号」出队，结果稳定可复现 |
| **循环依赖 100% 检出** | 判据：**拓扑序列长度 ≠ 课程总数** ⇒ 存在环；能输出具体环路路径与受阻课程，排课立即中止且不写脏数据 |
| **写入前防环** | 维护先修关系时先在内存图试算，会成环则拒绝写库（数据库层另有 `CHECK` 拦截自环） |
| **一键排课** | 按拓扑序为教学班分配「时段 + 教室」；硬约束（教师/教室/班级时段唯一、教室容量、教师工作量上限）全部满足 |
| **三层冲突兜底** | 算法层冲突矩阵 → 排课后独立自检 → 数据库唯一索引（`uk_teacher_slot` / `uk_room_slot` / `uk_class_slot`） |
| **学生选课七重校验** | 学籍 → 教学班状态 → 重复选课 → 先修通过 → 学分上限 → 容量 → 时间冲突，失败均给出可读原因 |
| **学生查课** | 周课表网格视图 + 明细表 + 先修进度 + 历史成绩 |
| **效率基准测试** | 本系统策略 vs 朴素/人工式策略的实测对比（耗时、冲突检测次数），并附规模扫描曲线 |
| **纯内存算法层** | 排课算法与数据库解耦，可脱离数据库做单元测试与基准测试 |

## 二、快速开始

### 1. 一键环境准备（含自动安装 MySQL）

本机若没有 MySQL，脚本会**以普通用户身份**下载并安装 MySQL 8.0 到 `~/.local/mysql`，无需 `sudo`：

```bash
bash scripts/setup_local_mysql.sh      # 下载 + 初始化 + 启动 + 建库建账号
```

> 若本机已有 MySQL，只需保证 `.env` 中的 `DB_*` 配置正确，可跳过本步。

### 2. 编译、初始化数据、运行

```bash
cp .env.example .env                   # 按需修改数据库口令等配置
bash run.sh init                       # 编译 + 建表 + 导入演示数据
bash run.sh                            # 进入终端可视化界面
```

也可以直接用 CMake：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
./build/scheduler init-db
./build/scheduler
```

### 3. 单元测试

```bash
bash run.sh test          # 或: ./build/scheduler_tests
```

## 三、界面与功能

主菜单（教务 / 学生两类角色分开）：

```
    1. 教务排课        (一键排课 / 拓扑序 / 循环依赖检测 / 全校课表)
    2. 课程与先修关系  (课程列表 / 先修关系维护, 自动阻止成环)
    3. 学生端          (登录后选课 / 退课 / 查看我的课表)
    4. 效率基准测试    (本系统策略 vs 朴素试错策略, 实测提升比例)
    5. 系统信息        (数据库连接 / 数据规模 / 初始化)
    0. 退出
```

- **教务排课**：一键排课、拓扑序与先修分层、循环依赖检测、循环依赖演练（临时注入环 → 自动报错 → 恢复现场）、
  全校课表、教师工作量、教室使用率、学生选课情况、排课审计记录。
- **课程与先修关系**：课程列表、先修关系一览、新增/删除先修关系（写入前自动试算防环）。
- **学生端**：学号 + 口令登录（演示口令 `123456`，演示账号 `2024001` / `2025001` / `2026001`），
  可查看周课表、可选课程（标注不可选原因）、选课、退课、先修进度、历史成绩。
- **效率基准测试**：同一数据集对比两种策略；规模扫描观察差距随规模放大。

### 命令行子命令（便于脚本化与自动化验收）

```bash
./build/scheduler init-db                 # 建库并导入演示数据
./build/scheduler cycle-check             # 循环依赖检测(有环返回码 2)
./build/scheduler topo                    # 拓扑序列 + 先修分层
./build/scheduler schedule                # 一键排课(落库)
./build/scheduler schedule --dry-run      # 仅预演不落库

./build/scheduler available 2024001       # 打印可选课程与不可选原因
./build/scheduler enroll 2024001 CS204-01 # 学生选课
./build/scheduler drop   2024001 CS204-01 # 学生退课
./build/scheduler benchmark 20            # 效率基准测试
./build/scheduler scaling 180             # 核心算法规模扫描
./build/scheduler stats                   # 学期统计概览
```

结论（如实呈现，含不利数据）：在 30 个教学班的演示规模下两种策略耗时接近 —— 线性扫描作用在很短
的数组上常数极小；随着规模增长，「哈希键冲突矩阵（O(1)）」相对「线性扫描（O(n)）」的优势持续放大，
180 班时约 **2 倍**，冲突检测次数减少 **99%**。复现命令与口径见
[docs/DESIGN.md](docs/DESIGN.md) 的「效率基准测试」章节。

### 头文件报红（找不到 `scheduler/xxx.hpp` 或 `mysql/mysql.h`）怎么处理

原因通常是编辑器没有拿到编译命令。本项目已通过 **`compile_commands.json`** 解决：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release   # 配置时自动导出编译数据库
# 构建后编译器/编辑器即可读到 build/compile_commands.json(项目根目录同时有软链接)
```
